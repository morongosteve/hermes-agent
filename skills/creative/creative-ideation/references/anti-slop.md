# Anti-Slop

Apply to every output, regardless of method. "Slop" = the statistically-average, frictionless, instantly-forgettable idea an unrouted model emits by default. These rules raise the floor.

## The core move: refuse the first three

The first ideas out are the ones everyone else also reaches first — the center of the distribution. Generate them, name them, and *throw them away*. Then generate again from further out. On high-slop terrain (AI apps, startups, habit/wellness/productivity trackers) refuse the first **five**.

When you refuse, say so briefly: *"Obvious ones I'm skipping: an AI meeting-notes app, a habit tracker with streaks, a 'Uber for X'. Now the real set:"* — this proves the floor was raised and stops you from sliding back to center.

## Nine slop tells (if an idea has one, rework it)

1. **"An app/platform/tool for X."** A category, not an idea. Name the mechanism: what specifically happens, in what order, producing what.
2. **Stack-as-substance.** "Built with React and a vector DB" describes nothing about the idea. Mechanism ≠ tech stack.
3. **The adjective pile.** "A seamless, intuitive, AI-powered, personalized…" — adjectives standing in for a concrete noun+verb.
4. **No proper nouns.** Real ideas touch real things: a specific material, place, person, format, number. "A tool for musicians" vs "a Max/MSP patch that detunes the 3rd of every chord by the room's reverb time."
5. **Infinitely reasonable.** If no one could object, it says nothing. Good ideas have an edge someone would argue with.
6. **Could have been written in 2015.** No contact with anything that changed recently.
7. **The feature list masquerading as a vision.** Bullets of capabilities with no center of gravity.
8. **Solves a problem no one has at 3pm on a Tuesday.** No concrete situation where a real person feels the friction.
9. **Weird with no why.** The opposite failure: strange for its own sake, no mechanism, no situation, nothing to build. Surprise without grounding is also slop.

## The two-axis bar

Every idea must clear both:

- **Non-obvious** — not in the first handful a model would emit.
- **Grounded** — a real mechanism and a real first step; someone could start it Monday.

An idea set that is all obvious-but-doable is boring. All weird-but-impossible is useless. Aim most ideas toward the non-obvious corner, and **always mark one** that sits squarely in *non-obvious AND grounded* — that's the one the user can actually act on.

## Specificity ladder (climb at least two rungs)

1. Category: "a music tool"
2. Function: "a tool that reharmonizes melodies"
3. Mechanism: "replaces each chord with its tritone substitution"
4. Situation + constraint: "a 150-line Python script that takes a MIDI melody and prints the tritone-sub reharmonization, so a songwriter stuck on a bridge gets three darker options in one command"

Rung 4 is an idea. Rung 1 is slop.

## Depth is not decoration

For each idea give: the concrete **mechanism**, the **situation** it binds to, and its honest **failure mode / tradeoff / who-it's-for**. These three are what make an idea land — measured in real evaluations. Do not cut them to be tidy.
